# localdex

A **local, offline Pokémon data package** — species, moves, abilities, items, learnsets, the type chart, a stat calculator and sprite URLs, all served from JSON bundled inside the package. No network calls at runtime, no API key, no rate limit.

The problem it solves: every tool I build around Pokémon needs the same reference data, and hitting a remote API for it is slow, flaky, and rate-limited. Here the data ships with the code, so a lookup is a synchronous object read.

The data is extracted from [`@pkmn/dex`](https://github.com/pkmn/ps) (the community extraction of Pokémon Showdown's dataset) by `scripts/pull-data.js`, which writes plain JSON into `data/`. Regenerating is a build step, not a runtime concern.

## Install

```bash
npm install localdex
```

## Use

```ts
import {
  Dex, calculateStats, typeEffectiveness, getWeaknesses, spriteUrl,
} from 'localdex';

// Lookup — names are normalised, so "Mr. Mime", "mr mime" and "mrmime" all work
const garchomp = Dex.pokemon('Garchomp');
garchomp.types;      // ['Dragon', 'Ground']
garchomp.baseStats;  // { hp: 108, atk: 130, def: 95, spa: 80, spd: 85, spe: 102 }

Dex.move('Earthquake').basePower;   // 100
Dex.ability('Rough Skin').shortDesc;
Dex.item('Leftovers').desc;

// Filtered search over the whole dex
Dex.searchPokemon({ type: 'Steel', gen: 9, minBst: 500 });
Dex.movesOfType('Fairy');

// Real stats at a level, with EVs / IVs / nature
calculateStats(garchomp.baseStats, 100, { atk: 252, spe: 252 }, {}, 'Jolly');
// → { hp: 357, atk: 359, def: 226, spa: 176, spd: 206, spe: 333 }

// Type chart
typeEffectiveness('Ice', ['Dragon', 'Ground']);  // 4
getWeaknesses(['Dragon', 'Ground']);             // ['Dragon', 'Fairy', 'Ice']

// Sprite URLs on play.pokemonshowdown.com
spriteUrl('Charizard-Mega-X', { shiny: true });
// → https://play.pokemonshowdown.com/sprites/ani-shiny/charizard-megax.gif
```

## API

Everything exported from the package entry point:

| Export | Signature | Returns |
|---|---|---|
| `Dex.pokemon` | `(name: string)` | `Pokemon \| null` |
| `Dex.allPokemon` | `()` | `Pokemon[]` |
| `Dex.searchPokemon` | `({ type?, gen?, tier?, minBst?, maxBst? })` | `Pokemon[]` |
| `Dex.move` / `Dex.allMoves` | `(name: string)` / `()` | `Move \| null` / `Move[]` |
| `Dex.movesOfType` | `(type: string)` | `Move[]` |
| `Dex.ability` / `Dex.allAbilities` | `(name: string)` / `()` | `Ability \| null` / `Ability[]` |
| `Dex.item` / `Dex.allItems` | `(name: string)` / `()` | `Item \| null` / `Item[]` |
| `Dex.learnset` | `(pokemonName: string)` | `Learnset \| null` |
| `Dex.canLearn` | `(pokemonName, moveName)` | `boolean` |
| `calculateStats` | `(baseStats, level = 100, evs = {}, ivs = {}, nature = 'Serious')` | `CalculatedStats` |
| `applyBoost` | `(stat: number, boost: number)` | `number` — stat at a −6…+6 boost stage |
| `typeEffectiveness` | `(attackingType, defendingTypes[])` | `number` (0, 0.25, 0.5, 1, 2, 4) |
| `getDefensiveMatchup` | `(defendingTypes[])` | `Record<attackingType, multiplier>` |
| `getWeaknesses` / `getResistances` / `getImmunities` | `(defendingTypes[])` | `string[]` |
| `getAllTypes` | `()` | `string[]` |
| `spriteUrl` | `(species, { style?, shiny?, back?, female? })` | `string` |
| `itemSpriteUrl` / `typeIconUrl` | `(name: string)` | `string` |
| `toSpriteId` | `(species: string)` | `string` — PS sprite slug |
| `toId` | `(name: string)` | `string` — lowercase alphanumeric |
| `getNatureModifier` | `(nature, stat)` | `1.1`, `0.9` or `1` |
| `getAllNatures` | `()` | `string[]` (25 natures) |

Types exported: `Pokemon`, `Move`, `Ability`, `Item`, `BaseStats`, `TypeData`, `Learnset`, `CalculatedStats`, `SpriteOptions`, `SpriteStyle`.

### The stat calculator

`calculateStats` implements the Gen 3+ formulas, including the two special cases that trip people up: Shedinja (base HP 1) always returns 1 HP, and nature modifiers apply after the floor, not before.

```
hp    = floor((2*base + iv + floor(ev/4)) * level / 100) + level + 10
other = floor((floor((2*base + iv + floor(ev/4)) * level / 100) + 5) * natureMod)
```

Defaults are level 100, 0 EVs, 31 IVs, Serious nature.

### Sprites

`toSpriteId` resolves a species name to the slug Showdown actually uses, by looking the species up in the dex for its `baseSpecies` and `forme` rather than guessing from the string. That's the difference between `charizard-megax` (correct) and `charizard-mega-x` (a 404).

`spriteUrl` styles: `ani` (animated GIF, default), `gen5` (static PNG), `home` (HOME artwork). `back` and `female` apply to `ani`/`gen5` only.

## What's in the box

`data/` is generated by `npm run pull-data` and committed, so a fresh clone or install has the data without a network round-trip. Don't hand-edit it — the next pull overwrites it.

| File | Entries |
|---|---|
| `pokedex.json` | 1,515 species and formes |
| `moves.json` | 938 moves |
| `abilities.json` | 314 abilities |
| `items.json` | 583 items |
| `learnsets.json` | 1,150 learnsets (2.8 MB) |
| `typechart.json` | 19 types |

## Scripts

```bash
npm run pull-data    # re-extract data/*.json from @pkmn/dex
npm run build        # tsc → dist/
```

`prepublishOnly` runs both, so a publish always ships freshly pulled data.

## Known limitations

- **Learnsets don't load in ESM.** `getLearnsets()` reaches for `createRequire` inside a `try`, which throws in the ESM build and falls back to an empty object — so `Dex.learnset()` and `Dex.canLearn()` return `null`/`false`. There is an async `preloadLearnsets()` in `src/data.ts` that works, but it isn't re-exported from `src/index.ts`, so it can't be reached from the published entry point. Everything else is a static JSON import and loads fine.
- **The data is a snapshot.** It's whatever `@pkmn/dex` had at the last `pull-data` run, not a live feed.
- **Sprite URLs point at `play.pokemonshowdown.com`** — the helpers build a URL, they don't fetch or bundle the image.
